# Concept Fable — 叙事编码学习技能

## 核心理念

人类大脑对故事的记忆效率远高于抽象定义。叙事会激活大脑中多个感觉区域，形成"具身认知"——读者不是在"记忆"故事，而是在"经历"故事。本技能利用这一机制，将抽象概念编码为具象叙事，让读者在不知不觉中完成概念建模。最后的"啊，原来讲的是这个！"的顿悟瞬间，会产生强烈的记忆锚定效果。

技法源自 Amanda Askell 关于利用 AI 辅助深度学习的 prompt 方法论。

---

## 用户可指定的选项（先确认）

| 选项 | 行为 | 示例 |
|------|------|------|
| **指定领域+概念** | 直接进入故事构建 | "用 concept-fable 讲信道容量" |
| **仅指定领域** | 从该领域挑一个好概念 | "讲一个博弈论的概念" |

| **仅要故事，不要解析** | 不加解析部分 | "只要故事" |
| **多角度版本** | 同一概念讲 2 个不同风格的故事 | "讲两个不同风格的" |
| **指定篇幅** | 默认 600-1000 字，可调整 | "讲短一点，300字" |
| **指定语言** | 默认中文，可切换 | "in English" |

## 执行流程

### 第零步：选择模式

使用 `AskUserQuestion` 询问用户偏好：

| 模式 | 说明 |
|------|------|
| 📖 **快速模式** | 故事 + 解析，直接出结果，适合快速理解一个概念 |
| 🎮 **完整模式** | 故事 + 猜谜 + 解析 + 交互追问，适合深度学习 |

**快速模式**跳过第四步（猜谜）和第六步（交互增强），故事输出完直接进入第五步解析。

**完整模式**走完全部六步。

如果用户在输入中已经暗示了偏好（如"只要故事"、"快速讲一下"），自动选择快速模式，不再询问。

---

### 第一步：确定概念与风格

**情况 A** — 用户已明确指定领域和概念  
→ 直接进入第二步，不赘述确认。

**情况 B** — 用户仅指定了领域但未指定概念  
→ 从该领域挑选一个适合用寓言展开的概念。挑选标准：有反直觉/精妙之处、核心机制可用日常隐喻映射、在该领域有代表性。

**关键规则：绝不能暴露概念名称。** 只能给一句模糊的、引发好奇心的预告，例如：
- "我从认知科学中挑了一个关于'自我欺骗'的精妙理论"
- "这个博弈论的概念会让你重新理解你为什么总是做那个选择"
- "它和你每天都在经历的一件事有关，但你从没注意到"

而不是：
- ❌ "我选了纳什均衡"
- ❌ "这个认知失调的概念很有意思"

然后直接进入第二步。

**情况 C** — 用户没有指定任何领域  
→ 使用 `AskUserQuestion` 工具分两轮引导：

1. **领域轮**：从以下领域库中提供 4 个选项 + "其他"（让用户自定义）：
   ```
   认知科学/神经科学 | 量子物理/热力学 | 经济学/博弈论
   进化生物学/生态学 | 计算机科学/信息论 | 社会学/复杂系统
   哲学(知识论/心灵哲学/伦理学) | 数学(拓扑/概率论/群论)
   心理学(社会心理学/认知偏差) | 语言学
   ```
2. **风格轮**：询问偏好的故事风格（寓言童话、武侠江湖、科幻未来、都市日常、古代传说、侦探推理、神话史诗）

---

### 第二步：构建寓言

动笔前，先做内部准备工作（**不要展示给用户**）——阅读 `references/writing-techniques.md`，从中选择：
1. **1 种开篇钩子**（必选）
2. **1 种故事引擎**（必选）
3. **至少 3 种写作技法**
4. **避开列出的 6 个常见坑**

然后写一个 600–1000 字（默认）的寓言故事。**呈现给用户时，只提一句故事风格即可**——例如："这次我用'发现之旅'的引擎来讲这个故事"或"今天用科幻风格来讲"。不要把钩子种类、技法清单等内部构造展示给用户。

**写完故事后，逐条检查（内部，不展示给用户）：**
1. 故事里有没有出现专业术语或概念名称？→ 有则替换或删除
2. 每个角色/事件是否都对应概念的一个要素？→ 删掉纯装饰性元素
3. 读到故事最后三分之一，读者能隐约感到"这好像在说某种规律"吗？→ 不能则加强暗示
4. 结尾是否用含蓄方式点题？→ 没有则修改，不要直接说出概念名称
5. 故事独立可读吗？剥离解析部分后还有文学价值吗？→ 没有则重写

**结构红线：**
- 开头不出现任何专业术语或概念暗示
- 每个角色、事件、冲突都对应概念的一个要素（不允许有"装饰性"元素）
- 故事最后三分之一，读者才隐约感到"这好像在说某种规律"
- 结尾用含蓄方式点题，不直接说出概念名称

---

### 第三步：展示故事

**默认方式：流式文字输出**

故事写完后，直接以纯文本形式输出给用户（600–1000字）。文字输出完成后，**默认用户已经阅读完毕**，直接进入第四步猜谜模式。

**HTML 可选项**

如果用户明确要求 HTML 格式（"用网页展示"、"生成 HTML 文件"），或你想主动提供精美排版版本，可以额外生成 HTML 文件并保存到 `d:
AICoding
eSkills`，但**这不会替代纯文本输出**。纯文本是默认且必须的，HTML 是锦上添花。

**关键原则**：不要让"用户是否打开了 HTML"成为阻塞条件。纯文本输出完，流程就继续。

---

### 第四步：猜谜模式（可选）

文字故事输出完成后，**在揭晓答案之前**，使用 `AskUserQuestion` 询问用户是否想先猜猜看：

> "故事讲完了。你想先猜猜这讲的是什么概念吗？"

- **如果用户选择猜**：等待用户回答。
  - **内部**：判断用户答案是否接近正确概念
  - **对外输出**：无论对错，先予以鼓励（"接近了！"、"很有洞察！"、"这个角度很有意思"），然后进入第五步揭晓答案
- **如果用户不猜**：直接进入第五步

**关键规则**：不要把内部判断过程（"用户猜对了"、"用户猜错了"）暴露给用户。直接给予鼓励性回应，然后揭晓。

这一步是猜谜模式的专属位置——在这之后才揭晓答案。其余交互模式（深度追问、反向创作、跨概念串联）放在第六步。

---

### 第五步：概念解析

按以下层次展开。**解析与故事之间用视觉分隔（HTML 用分隔线，纯文本用 `---`）。**

1. **揭晓时刻** — "原来，这个故事讲的是：**[概念名称]**"
2. **概念定义** — 2–3 句精准学术定义 + 所属领域
3. **隐喻对照表** — 表格：故事元素 → 概念要素 → 简释
4. **隐喻的边界** — 列出 2–3 条故事未能覆盖的概念要素或现实复杂性
5. **为什么重要** — 1–2 句现实意义

---

### 第六步：交互式学习增强（可选）

解析完成后，使用 `AskUserQuestion` 主动提供以下选项：

| 模式 | 说明 |
|------|------|
| **深度追问** 💬 | "有没有哪个隐喻元素你觉得对应不上的？"帮助排查理解盲区 |
| **反向创作** ✍️ | 让用户给同一概念编一个新寓言（2–3句梗概），AI 评估隐喻的准确性。**这是检验你是否真正理解概念的最佳方式——如果你能自己编出一个准确的隐喻，说明你已经内化了这个概念** |
| **跨概念串联** 🔗 | 如该概念与之前讨论过的概念有关联，主动指出并对比 |

默认行为：解析完成后直接提供以上选项供选择。
